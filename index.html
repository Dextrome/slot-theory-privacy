Privacy Policy - Slot Theory for Android

Last updated: September 2026  ·  Publisher: 7ants Studios  ·  Package: com.sevenants.slottheory

This policy applies to the Android version of the game Slot Theory, distributed through Google Play. It lists exactly what the game sends off your device, when, why, and how to stop it. The Steam version has its own policy.

In short: the game has no account system, no ads, no analytics SDK, no in-app purchases and no chat. It talks to one server (our leaderboard and crash-report backend, hosted on Supabase in the EU) in exactly two situations, both described below.

1. Data the game sends

1a. Leaderboard submissions (only when you choose to submit)

At the end of a run you can submit your score to the global leaderboard. Nothing is sent unless you confirm the submission. The first submission asks you for a short display name (up to 10 characters); if you leave it empty your entry shows as "Anonymous". A submission contains:

FieldWhat it is
Install IDA random identifier (UUID) generated on your device the first time the game runs. It is not derived from your device, your Google account or any hardware identifier. It lets the leaderboard keep one personal-best row per installation. Reinstalling the game generates a new one.
Display nameThe name you typed, or "Anonymous".
Run resultMap, difficulty, mode, score, whether the run was won, wave reached, lives remaining, total kills, total damage dealt, run duration in seconds.
BuildThe towers and modifiers you drafted (an encoded build code) and the build name you typed for it, if any.
Game versionThe version string of the game.

Once you have submitted a personal best, the game may re-send that same stored entry on a later launch if an earlier upload did not complete. It never submits a run you did not choose to submit. Viewing the leaderboard downloads other players' display names and run results; nothing about you is sent when you only view it.

1b. Crash reports (on by default; can be switched off)

If the game crashes, or was closed without shutting down cleanly, it writes a crash report to its private storage and uploads it on the next launch. The Settings > Send Crash Reports toggle turns the upload off; reports are then kept only on your device (at most 10, oldest deleted first). A crash report contains:

FieldWhat it is
Install IDThe same random identifier as above, so repeated crashes from one installation can be grouped.
VersionsGame version, game engine (Godot) version, platform name ("Android") and the Android OS version string.
Crash detailsThe kind of failure, the exception type and message, and the code stack trace at the point of failure, plus up to 8 earlier exceptions from the same session (type, message, stack, timestamp).
Session markerWhere the game was when it failed: map id, difficulty, wave number, whether endless mode was active, the number of enemies alive, the game's memory use in MB, the number of scene nodes, and a timestamp.
Report metadataA random report id, the time the report was written, and whether the build is a demo.

The Android version never attaches the game's log file to a crash report (the desktop version does). No screenshot, no input history and no device identifier is included.

1c. Network metadata

Any connection to a server exposes your IP address to that server while the request is handled. We do not store IP addresses in our data and do not use them for anything. Our hosting provider (Supabase) may keep standard transient connection logs under its own policy, linked below.

2. Data the game does NOT collect

  • No name, email address, phone number or contact details (the display name is a free-text nickname you choose)
  • No Google account information, no advertising ID, no device serial, no IMEI, no hardware identifiers
  • No location
  • No contacts, photos, files, microphone or camera; the app requests only the Internet permission
  • No gameplay analytics, telemetry, usage statistics or session tracking beyond the two items above
  • No advertising, no third-party analytics SDK, no in-app purchases

3. Data kept on your device

Settings, unlocks, achievements, your profile and run history, custom maps and the resume slot are stored in the app's private storage on your device. The app opts out of Android auto-backup, so this data is not copied to your Google account. Uninstalling the game deletes it. Nothing in this local data is sent anywhere except as described in section 1.

4. How the data is used

  • Leaderboard entries are used solely to show the global leaderboard inside the game.
  • Crash reports are used solely to find and fix bugs in the game.

Neither is sold, used for advertising or marketing, shared with third parties, or combined with any other data. Supabase processes the data on our behalf as a hosting provider and does not use it for its own purposes.

5. Retention and deletion

  • Leaderboard entries are kept indefinitely so your best run stays on the board. To have your entries deleted, contact us (below) with your display name and, if possible, the approximate date and map of the run. We delete them within 30 days.
  • Crash reports are kept for at most 12 months on the server and then deleted. You can request earlier deletion the same way.
  • Local data is deleted when you uninstall the app or clear its storage in Android settings.

6. Third-party services

  • Supabase (leaderboard and crash-report storage; EU region). Supabase Privacy Policy.
  • Google Play handles distribution and any payment. Google's own data collection (including Play's crash and ANR statistics) is governed by Google's Privacy Policy. The game itself does not integrate Google Play Games Services, Firebase or any Google SDK.

7. Children

Slot Theory is not directed at children under 13, has no account system and no chat. The only free-text fields are the display name and a build name for a submitted score. If you believe a child has submitted data, contact us and we will delete it promptly.

8. Your rights

Depending on where you live (for example under the GDPR) you may have the right to access, correct or delete the data we hold about you, or to object to its processing. Because the only identifier we hold is the random install ID, we can act on a request when you provide your display name or the details of the run. Contact details are below.

9. Changes to this policy

We may update this policy occasionally. The "last updated" date at the top reflects the latest change, and material changes are noted in the game's release notes.
